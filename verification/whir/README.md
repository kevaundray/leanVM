# Executable WHIR model and checked list binding

This isolated Lean project models leanVM's binary field, interleaved WHIR variant, originally pinned to [`edafd396120f453de6f75013f231bfda2049f217`](https://github.com/leanEthereum/leanVM/tree/edafd396120f453de6f75013f231bfda2049f217) and integrated normally with upstream [`10266a181437019400bc93d8dfbb373301ba8aa5`](https://github.com/leanEthereum/leanVM/tree/10266a181437019400bc93d8dfbb373301ba8aa5). It contains an executable concrete prover/verifier, checked concrete field and encoder mathematics, adaptive interactive **list binding** for the actual Lean verifier, and random oracle bounds for executable standalone and stacked adversaries. Fresh Rust differential checks are separate implementation evidence. The `DuplexRefinement`, `DuplexFraming` and `WHIRNativeSecurity` chain models proposed #552, not the deployed upstream transcript. Its conditional `2^-42` public random compression endpoint does not currently apply to deployed code.

## Reproduce

Dependencies are pinned by `lean-toolchain`, `lakefile.toml`, `lake-manifest.json`, and the external Rust harness's `Cargo.lock`. Lean is 4.34.0; Mathlib is `5ed2965256430c3649e86755f9576b54eca72435`. The imported ArkLib dependency is the [audited fork at `456f4f85acdde6aeb373794d0c5d0b133c2c11ea`](https://github.com/kevaundray/ArkLib/tree/456f4f85acdde6aeb373794d0c5d0b133c2c11ea), with the upstream discrepancy described below. The Rust harness uses toolchain 1.97 and production crates through relative path dependencies, without changing their APIs. Linux reproduction requires a working user systemd session; scopes cap each command at 16 GiB with no swap.

```sh
cd verification/whir
systemd-run --user --scope -q -p MemoryMax=16G -p MemorySwapMax=0 lake update
systemd-run --user --scope -q -p MemoryMax=16G -p MemorySwapMax=0 env LEAN_NUM_THREADS=2 lake build --wfail
systemd-run --user --scope -q -p MemoryMax=16G -p MemorySwapMax=0 env LEAN_NUM_THREADS=2 lake env lean Audit.lean
python3 differential/run.py
```

The runner builds and executes `whirModel`, executes the production Rust harness in release mode, and compares newly computed records. Its query mode also feeds actual production challenge limbs to Lean. It uses `/tmp/whir-lean-target`, two Cargo jobs, and one leanVM worker. Lean execution must emit no runtime diagnostic on stderr, including on malformed public inputs. There are no accepted-output snapshots to regenerate. Lean proof checking is separate from executable differential evidence.

## Refinement of the actual executable kernels

The operational kernels are polymorphic over their minimal operations, and the concrete prover/verifier call those same definitions specialized to `Concrete.E`. Their array refinements are not a parallel mathematical reimplementation. The concrete ring and field instances are now derived from the exact bit-level operations and kernel-checked irreducibility proofs.

- `ArrayAlgebra.dot_eq_sum` and `roundMessage_eq_sum` prove that the actual array reductions and mutable message loop compute bounded finite sums, including their original min-length and default-index semantics.
- `message_eval`, `roundMessage_cube`, `foldLane_cube` and `honest_round_cube` connect those actual executable definitions to `compactRound`, `roundConstant`, `roundQuadratic`, `foldFirst` and the existing generic `honest_round`, with an explicit equivalence for the remaining Boolean coordinates.
- `honest_foldLane` and `honest_foldLow` prove actual round evaluation equals the dot product of the actual folded arrays, for every aligned shape and equal witness/weight lengths over any characteristic-two commutative ring. `dot_weightGlue` and `roundMessage_weightGlue` prove the actual batched target and intro message match the actual batched weight.
- `ArrayLayout` proves actual array rotation versus `Layout.terminalPoint`, actual `getD` padding and base-encoder leaf reversal versus the list specification, and exact low/top fold indices and lengths. Oversized `rotatePoint` inputs clamp because `Array.extract` clamps; list rotation wraps. The universal bridge uses `min k size`, while the direct protocol bridge states `k ≤ size`. Padding similarly records that a valid live prefix fits the padded width.
- `Protocol.verify` now calls `VerifierState.fold`, `batch` and `checkTerminal` for every algebraic transition. `ReplayRefinement.fold_preserves` and `batch_preserves` prove these exact functions maintain the interpreted array state. `trace_preserves` composes arbitrary numbers of those actual transitions, including block/level changes; `trace_terminal` proves that an honest trace ending in one witness scalar passes the actual Boolean terminal checker. The power-of-two specialization discharges the pairing-shape condition for the protocol's layouts.

`OperationalRefinement.verify_ok_iff` identifies successful execution of the actual nested verifier with its checked transition trace. `QueryRefinement` and `BatchingRefinement` discharge the actual authenticated-row/induced-weight identities; `TerminalRefinement` connects the actual residual MLE to successive array folds. The soundness proof follows adversarial, not just honest, executions through these same functions. A universal theorem that the full optimized Rust prover and verifier refine this Lean program is not claimed.


## Intentional differences from original WHIR

The implementation commits in K = GF(2^64), challenges in E = GF(2^192), and uses additive domains and the novel polynomial basis. The original multiplicative WHIR folding formulas cannot be copied into characteristic two. Quadratic messages contain only the constant and quadratic coefficient; the linear coefficient is reconstructed as `claim + quadratic`.

There is no commitment-time OOD sample, following Flock. The appropriate security relation is **list binding**, not unique binding. Subsequent OOD claims occur after new commitments. The production protocol sends intro polynomials one message ahead. `CausalGame` and the checked history/replay modules preserve that causal schedule, including the invisible final tail challenge; strategies cannot inspect future tape coordinates.

L0 folds the top witness variables because each interleaved lane is a contiguous stack block. Codeword lane order is reversed, so missing zero-tail lanes become leading zeros in a leaf. Only the live suffix is transported. Caller-coordinate rotation must not be applied to per-level induced weights.

Queries are sampled with replacement in binary-sized stratified groups. They are not iid uniform columns and are not deduplicated. The sampling proofs derive the exact finite distribution from uniform raw E chunks, including chunk sharing, unused bits and repeated cosets. Random-oracle compilation counts every allocation and final completion. The advertised numerical bounds are deliberately **unground**: no proof-of-work amplification and no numerical 128-bit security claim is made.

Ring switching combines all 64-slice claims by a gamma challenge before drawing the six-stage additive map. Each claim's scale remains inside that map. Claim points need not be prefixes of one another. `RingPCSGame` proves false original family/point claims lead to either a quantified ring-map/batching event or false transformed WHIR claims, using the same commitment-time K-witness list. `StackWHIRROM` includes gamma, six map challenges and lambda in one initial 8E allocation, not eight independent oracle opportunities.

## Why this formalization approach

The inspected upstream ArkLib revision is [`35ddcaa83f683011f944f58904be779495a5709a`](https://github.com/Verified-zkEVM/ArkLib/tree/35ddcaa83f683011f944f58904be779495a5709a/ArkLib). Its sumcheck implementation separates executable coefficient messages from polynomial interpretation; `Interaction/ComputableSoundness.lean` proves an actual executor/adversarial-strategy bound. Its Reed-Solomon Johnson/MCA infrastructure is now an imported and instantiated dependency, not merely a precedent: `JohnsonMCA`, `JohnsonNumerics` and `JohnsonListNumerics` discharge the required concrete field, agreement-set and numerical hypotheses.

Dependency auditing found a genuinely false admitted repeated-size `Fin.sumCases` identity: the sizes `[1,1]` provide a kernel-checked counterexample. [ArkLib PR #1297](https://github.com/Verified-zkEVM/ArkLib/pull/1297) removes that unused identity and an unused admitted polynomial-basis placeholder, and repairs the axiom baseline. The pinned fork contains that fix. Other admitted legacy ArkLib interfaces are not silently treated as proofs of WHIR, Merkle security or Fiat-Shamir security; every imported dependency used by a `Whir` theorem is checked transitively by `Audit.lean`.

The inspected Ironwood revision is [`86e3c7026db8c9af27ca731e6b5c7f2d8fc7f0fc`](https://github.com/zcash/ironwood/tree/86e3c7026db8c9af27ca731e6b5c7f2d8fc7f0fc/Zcash). `Arithmetic/NatKernelEquiv.lean` uses a representation map instead of an assumed implementation/spec isomorphism. `Arithmetic/FftSpec.lean` decomposes actual FFT refinement into bit reversal, twiddles and rounds. `Arithmetic/FastMsm.lean` uses a proved `csimp` equality rather than an unchecked implementation replacement. `Meta/AxiomCheck.lean`, `TrustBoundary.lean` and `CensusCheck.lean` motivate direct endpoint and elaborated-environment auditing. Ironwood's multiplicative FFT theorem is not an additive-NTT proof for leanVM.

## Security endpoints and crypto games

`InteractiveSoundness.adaptive_list_binding` proves the actual `CausalGame.AdaptiveListBinding` predicate, not just its definition. For each commitment oracle and lane count it chooses `InitialCandidates.witnesses` before quantifying over public claims and the adversarial strategy. `production_probability` bounds accepted false openings by 2^-73 when the number of public claims is at most 2^64, for every production profile. The candidate list is a mathematical finite list; enumerating it is not required by the executable verifier.

The proof constructs concrete initial-batching, fold-restoration, OOD/query-restoration and terminal-collision events. `CausalPrefix` and `CausalStrategy` prove that each event depends only on the current challenge and the strictly earlier reply/tape prefix. Field cardinalities, the additive encoder's RS interpretation, Johnson/MCA list size, same-agreement-set transfer, concrete OOD separation, sampling distribution and all numerical side conditions are proved rather than packaged as a missing-soundness premise.

`TypedOracleCompiler` executes adaptive oracle machines with a private global memo table. Repeated or cloned requests retain their answers; partial projections do not disclose the rest of a sample. Its whole-history completion is causal, and every payoff agrees with the reference oracle execution. At most `B * (K + 1)` challenge allocations are charged for request depth at most `B` and at most `K` adversarial requests, including the final verifier completion.

`WHIRROM.rom_list_binding_numeric` bounds actual standalone false acceptance by `min 1 (B * (K + 1) * 2^-79)`. `StackWHIRROM.rom_list_binding_numeric` gives `min 1 (B * (K + 1) * (2^-79 + ringCharge cap))` for original stacked family/point claims. Both prove their concrete replay parsing, strict-prefix event correspondence and terminal trace cover; neither asks the caller to assume accepted false openings are covered by bad events. Immutable statement catalogs and root oracles are explicit inputs, not mutable values chosen after a challenge.

`DuplexRefinement`, `DuplexFraming` and the `WHIRNativeSecurity` public compression chain model the framed byte duplex now deployed at `f11f84f585680cf10f676bb4d9ae1a67e26547ca`. The capped conditional `2^-42` endpoint concerns that mode and the modeled unanchored native WHIR experiment, under the explicit unproved DMV coupling and resource premises below. It is not a concrete BLAKE2s security bound or a theorem covering every deployed caller. In particular, the physical root-header decoder has not been migrated to the new immutable anchor records and opening frames, and the separate anchor codec uses an independent scalar-output experiment rather than the deployed cursor-based byte stream. Generic verifier vector sampling also uses repeated scalar draws, so its exhaustion behavior is not the native duplex's whole-request preflight.

`DuplexRefinement` implements that pinned source's buffered stream, held final block, absorb/squeeze roles, full chaining value, vector sampling, cloning, nonce/grinding and limits. `DuplexEncoding`, `DuplexFraming` and `WHIRHistoryKey` prove actual framing inverses, message/template injection, canonical WHIR history encoding and the structural DMV conditions. `DuplexCompression` implements the actual BLAKE2s compression evaluator. Structural framing correctness is not a proof of the probabilistic DMV theorem.

`DuplexModeGame` defines finite real public-compression and ideal raw-random-oracle/simulator games for adaptive direct and construction queries, including auxiliary and verifier work. `PublicRandomCompressionDMV` now assumes only the actual universal view-distinguishing inequality; its redundant `simulatorBound` certificate field has been removed because `DuplexPublicSimulator.simulatorBound` proves the pinned simulator's metering. Structural reconstruction and metering do **not** prove the stochastic inequality. The finite-game coupling/H-coefficient argument for the actual mode and simulator remains a mathematical proof obligation.

`ConcretePrimitiveGap` is retained as a precisely named **full-public-view replacement premise**, not a standard computational hash-security assumption. `knownAnswerAdversary` makes one direct primitive query, and `knownAnswerDistinguisher` compares its answer with a local evaluation of public BLAKE2s. `knownAnswer_concreteProbability` is exactly `1`; `knownAnswer_realProbability` is exactly `2^-256`. The kernel-checked `concretePrimitiveGap_knownAnswer_lower_bound` therefore proves `primitiveLoss >= 1 - 2^-256` whenever `Q >= 1` and `Allowed` includes this pair. Ordinary efficient classes include this elementary observer. Efficiency, collision resistance or a stronger implementation audit cannot justify a small full-view loss. This counterexample applies to the public primitive experiment used for proposed #552 and does not refute the separate random-compression DMV claim.

Consequently `WHIRNativeSecurity.concrete_list_binding` is a formal conditional inequality, **not a useful ordinary computational-security theorem for deterministic BLAKE2s**. Excluding the observer solely to manufacture a small gap is not a standard assumption or a completed reduction. A useful concrete theorem would need a justified, correctly scoped assumption about the actual protocol/final event or another cryptographic reduction; none is silently substituted here. No such standard-assumption reduction has been proved.

### Native source, caller and Merkle composition

`WHIRPhysicalDriver.verifyAfter` runs an arbitrary attacker-input source followed by the actual native verifier, not an arbitrary source returning fabricated acceptance evidence. Its one `ProductionRegistry` supplies both the physical CPU/recursion decoder and logical caller catalog, including production placements and lane counts. `WHIRPhysicalBinding.nativeFailure_or_frozen` proves that actual wrong native acceptance implies the causal raw-oracle failure or an ordinary Merkle primitive failure. Original caller decoding, actual sampled histories, authenticated-row restoration, first-frozen catalogs, opening-input lengths and coverage by actual compression calls are derived internally, not theorem premises.

`WHIRNativeEvent.distinguisher` receives only the completed public result. `WHIRObservableSource.observe` reconstructs its chronological cache, labels and immutable first-registration state from public source events and physically returned completion records; neither receives a source program, adversary coins, simulator seed or total oracle. `WHIRSourceFrozenPrefix.actual_backfill_retained` connects every retained snapshot to its actual earlier full-compression prefix, including direct calls and hidden construction calls. The candidate list is `InitialCandidates.witnesses` of the first-frozen commitment, not a list selected after inspecting the claimed family; `bindClaims_witnesses` proves that binding claims leaves this list unchanged, and `WHIRPhysicalDriver.native_list_bound` bounds its cardinality by `2^32`.

`WHIRNativeSecurity.random_compression_list_binding` composes the actual native event with the checked adaptive raw-oracle bound, the explicit DMV game assumption, and `PublicMerkleProbability.opening_probability_bound`. Write `A = a + b` for attacker plus native-verifier source budgets, `R = (Q+1) * (free + (Q+1) * (40+1))`, and `epsilon = 2^-79 + ringCharge cap`. The strengthened bound is `min 1 ((40 + callerOutputCap) * (A+1) * epsilon) + min 1 (choose(Q,2) / 2^256) + (Q*R + 2*Q*(Q-1)) / 2^256`. `PublicMerkleProbability.badTargets_card` now bounds the actual causal targets by `R + 4*history.length`; `risk_bound` sums those per-step counts instead of replacing pair-child/CV targets by the final budget. This tightens the previous Merkle numerator `choose(Q,2) + Q*(R+3*Q)` without adding any premise, and flows through `WHIRSourceMerkleSecurity.loss` to both native endpoints. The physical envelope remains source-only and noncircular: `A + A*(pathFactor*A) + pathFactor*Mf <= Q`; verifier and final-path caps hold on reachable attacker outputs, and zero-cost commitment announcements have their own `FreeAnnouncements` resource. The concrete endpoint adds the explicit replacement loss subject to the impossibility boundary above.

`SuccinctPointWeight.eqAt_eq_mle`, `SuccinctRingGroups.sourceStackWeightAt_eq_batch_mle`, and `InducedTerminalRefinement.nativeBasisAt_eq_mle` connect the actual plain/strided selectors, shared-prefix ring evaluator, inverse-Frobenius coefficients, and native induced-basis recurrence to their dense meanings. `AccumulatedTerminalRefinement.stack_terminal_equivalence` composes every saved OOD/query context with the rotated original caller point. `WHIRNativeArithmetic.sourceVerify_refines` proves the complete scalar-only native-style verifier loop refines `Protocol.verify`, under explicit public shapes and authenticated-row premises; it does not assume caller-weight or terminal-evaluator equality. `WHIRNativeErasure.nativeVerify_erased` removes only ghost commitment oracles, preserving actual query rows and errors.

`SuccinctPointWeight.dimension_le_of_block_bound` derives coordinate dimension from full-block containment. `selector_lt_of_block_bound` proves the shifted high selector fits the suffix consumed by the native evaluator and is used by `region_mle`, hence the native `eqAt_eq_mle` chain. `Shape` no longer redundantly asks for dimension bounds in addition to containment; `Shape.point_iff` and `Shape.strided_iff` prove equivalence to the previous complete guard predicates. `WHIRCallerSupport.production_point_nativeShape` uses the reduced premise set. Offset alignment and strided-slot bounds remain genuine requirements, not consequences of the historical source pin's range-only guard.


The model also fixes a Lean L0 extraction discrepancy: authenticate the full padded leaf, discard only its leading absent lanes, and reverse the occupied lanes exactly once at the protocol boundary. Separately executed pruned and full-width regression cases exercised the real parser and hash path. This is a model correction, distinct from the Rust guard fix below.

## Trust boundary and remaining limitations

`Audit.lean` discovers every exported theorem in the elaborated `Whir` namespace and computes its transitive axioms. It rejects project axioms and every dependency axiom except `propext`, `Classical.choice` and `Quot.sound`. Selected principal algebra endpoints additionally retain `#print axioms` commands. No `sorry`, `admit`, `native_decide`, unsafe proof execution, or new correctness axiom is used in completed chains. Running the compiled model and Rust still trusts their compilers/runtime; differential testing is evidence for tested inputs, not a kernel proof of their correspondence.

The proved mathematical boundary includes concrete K/E field laws, the Lean additive encoder's RS interpretation, actual length-checked verifier refinement, the ring-map error bound, Johnson/MCA and OOD instantiations, adaptive interactive list binding, typed and exact-raw oracle bounds, native scalar arithmetic, original CPU/recursion caller construction, public source reconstruction, first-frozen Merkle transport, and the strengthened shared-compression collision/target-hit probability bound. The remaining categories are separate:

- **Unproved mathematical reduction:** `PublicRandomCompressionDMV.distinguishing` for `DuplexPublicSimulator.simulator Q` and the pinned #552 mode. Framing, public-chain recognition, seed reconstruction and actual RO-query metering are proved; the adaptive real/ideal probability coupling and its DMV birthday bound are not.
- **Concrete cryptography:** `ConcretePrimitiveGap Q registry.iv primitiveLoss Allowed` and membership of the final native event in `Allowed`. The new known-answer theorem prevents a small loss for ordinary efficient full-view classes. The formal concrete endpoint remains conditional; a justified final-event computational assumption or standard-assumption reduction is missing. Neither collision resistance nor arbitrary exclusion of the observer is supplied as a substitute.
- **Resource/model domain:** the native endpoint retains `before` (`Counts a` for every attacker coin), `verifierBudget` (reachable `WHIRPhysicalVerifier.sourceBudget <= b`), `paths` (reachable terminal `pathCost <= Mf`), `announcements` (`FreeAnnouncements free`), and `envelope` (`WHIRSourceBackfill.budget context (a+b) Mf <= Q`). Finite coins, caller output caps, valid caller shapes and first-registration semantics belong to the mathematical experiment. These are not small-gap crypto assumptions.
- **Implementation/compiler correspondence:** natural-number Lean shape arithmetic does not prove arbitrary malformed `usize` shifts/additions safe. The historical source pin's selector guard is weaker than `Shape`; #599 now adds alignment and strided-slot checks, but its new typed APIs, closed-form lane fold, query normalization and error behavior have not been universally refined by this draft. Valid constructed CPU/recursion layouts and arbitrary public PCS statements must not be conflated. The optimized/streamed Rust NTT/commitment kernels, universal Rust-to-Lean refinement, compilation and runtime remain outside the kernel conclusion.
- **Deployment/security target:** the public mode theorem models the #552 byte duplex now deployed at `f11f84f585680cf10f676bb4d9ae1a67e26547ca`. Its conditional `2^-42` endpoint requires the stated DMV, source, valid-state and resource premises and concerns the modeled unanchored native event. It does not cover the new anchor frames or establish deterministic BLAKE2s security. Ground list binding is not unique binding. No grinding amplification or numerical 128 bit whole system security conclusion is asserted.

Merkle transport gives a fixed first registration row oracle or explicit primitive game failures. It does not assert collision resistance as a field axiom or equate collision resistance with random oracle behavior. The mathematical production driver, caller geometry, physical source, observable reconstruction and final probability composition are included through the `WHIRNativeSecurity` root import. ## Stronger binding and extraction investigation

`CommitmentAmbiguity` checks exact root-locality of the executable verifier, including its error result, and a valid small interactive commitment with two incompatible accepting opening sessions against the same immutable oracle. It separately checks the actual production first-query parity probability. This is an ideal causal interaction result with supplied independent challenges, not a demonstrated attack on deployed Fiat-Shamir.

`CommitmentAnchor` defines commitment identity as the complete immutable root, shape, anchor point and advertised value. The root-fixed candidate list precedes the one fresh uniform extension-field anchor point. Supported padding is injective, and the anchor weight is truncated to the occupied lane prefix while preserving the actual padded witness MLE. Outside the point-only collision event, every malicious choice of advertised value selects at most one supported candidate simultaneously across all later sessions. The actual causal verifier checks this same anchor in every opening batch; its unique-opening failure bound conditional on an unambiguous anchor is the original opening ledger with the additional anchor claim counted.

The checked anchor ambiguity term is `choose(L,2) * dimension / |E|`, bounded by `2^-124` at the proved list cap and supported production dimensions. This is only list selection ambiguity, not whole system security. `ConcreteSecurityBudget` separately proves a capped `2^-42` list binding ledger for the conditional public random compression model of the now-deployed #552 mode and demonstrates why its stated caps do not yield a `2^-43` ledger. That endpoint retains the unproved DMV premise and modeled unanchored source event; it is not the composed anchored endpoint. The extra commitment time challenge still needs its cursor-based Fiat Shamir and concrete cryptographic composition.

`KnowledgeExtraction` defines executable bounded rewind access and the actual acceptance-plus-extraction-failure experiment. Its checked record-only sparse-decoder impossibility result and exact reconstruction threshold concern the actual additive encoder. It does not provide an efficient successful knowledge extractor or a knowledge soundness theorem. Mathematical classical choice in the anchored binding selector is explicitly not an extractor.
