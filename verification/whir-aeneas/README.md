These artifacts are source extraction work, not a completed Rust-to-Lean verifier-equivalence proof. They do not establish a security level, knowledge soundness, unique binding, or universal equivalence between Rust acceptance and the proof model.

## Current hash boundary

The current source includes upstream PR 555's x86-64 compression assembly and batched Merkle hashing. These kernels are not replaced with a slower portable implementation for extraction. The compression interface is `WhirAeneas.Hash.SatisfiesRfc7693`, defined using the actual `LeanVMCircuits.Blake2s.Rfc7693.F` imported from the circuits project at `404c8fd0928ea6abea1facd220b91ee7464bd810`. That dependency and the generated portable compression both check in the same Lean 4.34 environment as the WHIR model.

`extract.sh portable` extracts the actual `primitives::hash::compress_portable` without editing its generated Lean. Execution agrees with the shared RFC definition and the native compression on both final flags and counter boundaries. These finite observations are not the universal portable-compression theorem, which remains to be proved.

The conditional native extraction separates compression and batched hash entry points from the supported verifier body. The required batch contract is content-level RFC hashing with exact output length and input order, including the zero prefix of padded leaf images. It must not assume Merkle authentication or verifier soundness. The x86 assembly, Lanes32 memory operations, and SIMD/batch backends remain tested-only boundaries until separate proofs discharge their contracts. Neither the generated function nor a conditional correspondence theorem would verify allocator, OOM, uninitialized-buffer implementation, or ABI frame behavior. This is not an unconditional Rust-to-Lean equivalence claim.

The private, single-caller `#[inline]` helper `fiat_shamir::merkle::hash_packed_leaves` belongs to the same hash boundary as `hash_pairs` and `hash_many`. Given a valid descriptor from `LeafHasher::new`, exactly `n` packed rows and successful allocation, it must return exactly `n` digests in row order. Digest `i` is the shared RFC BLAKE2s hash of the complete leaf image: the descriptor's zero prefix followed by packed row `i`. Deduplication, row count and width checks, the `row_words <= leaf_words` guard, `LeafHasher::new`, byte packing and all authentication decisions remain outside this helper and must be translated and related separately. The helper preserves the existing uninitialized allocation, fill and ownership conversion pattern; this content contract does not verify those memory operations.

### The composed verifier theorem

`WhirAeneas.Replay.verify_eq` (`WhirAeneas/Compose.lean`) is proved against the same pre-607 extraction. For an opening verifier whose transcript answers `Script.tape s` (followed by anything), the generated `verify` returns `Ok` exactly when `WHIRNativeArithmetic.nativeVerify c (Script.chal s) n_lanes (encode target) callerAt (Script.prf s)` returns `ok ()`. Its premises are exactly: 64-bit `usize`; `ArithModel`, `RowModel`, `NormalizerModel`, `EnsureModel` and `CallerModel` for the dictionaries; the `Transcript` tape interface; the element clone is the identity; `ConfigRel config c log_n` (which includes level folds below 62); `Challenges.valid` of the script's challenges; and `ScriptShape`, which now also bounds the total number of out-of-domain contexts below `usize::MAX` (`small`), the capacity of the source's single context vector. A lane count of zero or above `2^initial_k` is rejected by both. The proof composes `run_eq` (the level-0 prefix: lane checks, initial round, initial folds, root, out-of-domain claims, query phase, the row reversal `run_loop0_eq`, `base_enforced_eq` with `enforced_base` in `base_model_eq`, the batch and the next oracle) with `run_loop_eq`, an induction over the remaining levels whose middle step is `mid_level_eq` and whose last step is `last_iter_eq`, each matched to the model's `verifyLevel` by `script_level_any`. `nativeVerify_ok_iff` and `nativeVerify_lanes` read the model's verifier around its checked level replay.

`WhirAeneas.Sampling.sample_queries_ordered_eq` (`WhirAeneas/Sampling.lean`, same pin) proves the generated `sample_queries_ordered` for `block_len = 2^d`, `0 < d < 64`, whose challenger's `sample` returns the squeezes `sq` in order (`SqueezeTape`), with `sq` of the model's length `ceil(count / floor(192 / d))`, returns positions whose values are exactly `Concrete.deriveQueries d count` of the squeezes read as extension elements (`toE`: the three limbs as `Concrete.E`). It covers the chunk extraction across limbs (`chunk_core`, `push_chunks_eq`), the squeeze loop (`sample_loop_eq`), the generated `strata` against the model's `strata` (`strata_eq`) and the stratum replacement (`place_loop_eq`). With the native opening verifier's `sample_queries` (which calls `sample_queries_ordered` with `1 << depth`), this discharges the `queries` read of `Transcript` and the `queries` field of `ScriptShape` from the squeezes the duplex returns.

`ReplayAudit.lean` audits 1041 theorems (post-607 extraction) of `WhirAeneas.Fold`, `Query`, `Replay`, `Sampling` and the generated `ReplaySource`, with only `propext`, `Classical.choice` and `Quot.sound`.

Merkle contract, post-607 (extraction blocked, see `extract.sh merkle`: Aeneas rejects returns inside nested loops in `PrunedMerklePaths::open` and the `as_chunks` slice pattern in `from_hint`). What the composed theorem needs from the native `open_rows`, and what linking to the model's `AuthenticatedRows` additionally needs, is exactly: (1) decoding: `from_hint(hint, n, w)` returns the rows as the first `8nw` bytes read as little-endian words in sorted distinct query order and the rest as whole 32-byte siblings, else nothing; (2) authentication: `open(root, 2^depth, queries, w, leaf_words)` returns openings iff recomputing every node on the queried paths, with leaf digest the content-level RFC BLAKE2s hash of the zero prefix followed by the packed row and parents `hash_pairs` of the children, consumes every supplied sibling and yields `root`; the opening of query `i` is the row stored at the sorted position of `queries[i]`; (3) binding, the only non-functional premise: for the committed oracle of the level, any row accepted at position `q` against its root equals the oracle's row `q` (collision resistance of the hash on the leaf images and pairs involved). (1) and (2) give the `rows` read of `Transcript`; (3) with them gives `AuthenticatedRows`. Removing the batched and assembly hash boundary for (2) is possible on the portable one-hash-at-a-time `open::<Portable>` of PR 606.

The Merkle-opened rows are outside the replay surface. Their contract, as the composed theorem uses it, is the `rows` read of `Transcript`: `open_rows` returns `Ok` with exactly the tape's rows, so the model's `Opening.rows` are those rows' interpretations. Linking those rows to the committed oracle (the model's `AuthenticatedRows`, needed by `nativeVerify_refines`) requires extracting `pcs::merkle` (`PrunedMerklePaths::open` and `from_hint`, whose hint is every row's words little-endian then the 32-byte siblings, with no length) under the content-level hash interface described above.

`extract.sh merkle` is that surface: roots `PrunedMerklePaths::open` and `PrunedMerklePaths::from_hint`, with `hash_pairs`, `LeafHasher::hash`, `zero_prefix_state` and the `primitives::hash` kernels opaque, into the ignored `failures/merkle`. Charon retains both roots with bodies. Aeneas does not translate them yet. `open` stops at its pre-pass with "Returns inside of nested loops are not supported yet": the `?` on the sibling iterator inside the per-level pair loop, and the `?` on each path's `binary_search` inside the per-query level loop. `from_hint` alone fails on the empty-slice pattern `let (words, []) = rows.as_chunks::<8>()`, which lowers to a `&raw const` with slice metadata ("Unsupported operation"). Both also reach standard-library operations the backend does not model (`as_chunks`, `split_at_checked`, `sort_unstable`, `dedup`, `binary_search`, `windows`, `chunks_exact_mut`, `u64::to_le_bytes` and `from_le_bytes`, `Box::new_uninit_slice` with `assume_init`, `flat_map`, the generic `Iterator::map` and `Option`'s `?`), which a source repair would replace with index loops and explicit matches as on the replay surface.

### Discharging ArithModel with portable arithmetic

PR 606 adds `const` portable `F64`/`F192` multiplication, squaring and inversion and a portable `Arith` used by a single-threaded verifier. Once it lands: (1) add its portable `F64`/`F192` operations and the portable `Arith` impl as replay roots, so the dictionary is generated rather than assumed, and check the root validator retains them; the current extraction already reaches the software `clmul` path for `F64` multiplication. (2) Prove the generated `F64` multiply, square and inverse equal `Concrete.kmul`, `kmul a a` and `kinv` on `UInt64` values (carry-less product, reduction by the production modulus, inversion by the fixed exponent chain), and the `F192` operations equal `Concrete.E.mul`, `E.add` and the model inverse on limbs, using the model's `FieldExtension` ring structure. (3) Prove the provided methods `eq_table_prefix`, `powers` and `mle` (translated from `fiat_shamir::arith`) from the basic operations, by loop invariants against `Concrete.eqTable`, `Concrete.powers` and `Concrete.mle`. (4) Conclude `ArithModel portableArith encode const` with `encode` the limb map and `const` the same map on constants, and the normalizer premise from the generated `Normalizers::new` against `subspaceRoots`. The native `VerifierState` dictionary dispatches to the optimized kernels, so the discharge then applies to the native verifier only through a separate equality of those kernels with the portable code, or by the portable verifier being the one composed.

## Remaining generic extraction failures

`toolchain/check-loop-borrows.py` checks the pinned Aeneas outcome for each shape in `toolchain/tests/loop_borrows.rs` and fails if any outcome changes; it also attributes lost trait-clause type variables to their function. Behavior-preserving source changes removed every verifier root cause the reproducers name: loops under a borrow of a value holding a borrow now run in helpers over the slices, the replay state holds no configuration borrow, returned borrows are indexed instead, prefix groups name points by index, the Merkle level fold returns its parents from a helper and reads siblings by index, out-of-domain replays use an explicit loop instead of a capturing closure, arithmetic-only loops are generic over `Arith`, and `WeightAt` names its element type. The native-hash-interface extraction now translates every verifier body; the only failure left is the test harness `verify_instance`, which reads an `Option<&'static [u8]>` field through `&Instance`, the nested-borrow shape `rejected_view` reproduces.
