# Actual Rust WHIR extraction

These artifacts are source extraction work, not a completed Rust-to-Lean verifier-equivalence proof. They do not establish a security level, knowledge soundness, unique binding, or universal equivalence between Rust acceptance and the proof model.

## Pins and reproduction

The extraction source is the normal merge `4ad777ca` of the PCS-overhaul base and protocol branch at `12eea88c41dd964d82d4eb15ce91bba17ef91339`, followed by the semantics-preserving guard repair `1abc198a`. The separate Merkle authentication-phase split `826dd798` is local and not integrated into the protocol PR. The handwritten proof-model dependency is proof PR 551 at `fa13f619f560c1aa99200edbdd48480b4849b3f1`, with Lean 4.34.0 and mathlib `5ed2965256430c3649e86755f9576b54eca72435`. CompPoly resolves to that model's recorded lock at `df591bb8c6745126d1d72f5243faae3022b0432a`.

The extraction release is Aeneas `nightly-2026.10.09-d119a47`, commit `d119a474f852781f8ae88a85424f2f8ba8407b82`, and Charon `798016509139eb51f0d764645f76d068d34ba5f6`, using Rust nightly 2026-09-17. Its original backend targets Lean 4.31.0. The recorded backend portability patches now check the backend, generated public arithmetic-dictionary code, and standard-library content lemmas in the same Lean 4.34.0 environment as the actual handwritten model. `toolchain/backend-provenance.json` records each patch hash and the scope of this check. The scripts verify release and executable checksums.

Run `./verification/whir-aeneas/extract.sh statement` from the repository to regenerate `llbc/statement/pcs.llbc` and `WhirAeneas/Generated/Statement` from the actual release-mode `pcs::stack::Statement::check`, which includes `StackClaim::is_well_formed` and its helpers. There is no manually maintained duplicate Rust verifier. The earlier separate claim root and the historical range-only statement artifact are retired; the statement root extracts the same guard functions.

Run `bootstrap.sh build` in this directory to install the checksum-pinned backend, apply the recorded semantic and Lean 4.34 portability patches, obtain the root package's declared Mathlib cache, and build the backend. Heavy compiler and extraction commands are memory-capped and serialized through `/tmp/leanvm-heavy.lock`. The shift patch accepts the full unsigned or signed right operand emitted by release MIR, without narrowing to `U32`, and proves the masked-shift and signed-modulo identities. The iterator alias patch makes the definitionally equal canonical owned-vector iterator type usable by ordinary rewriting. The string-literal patch replaces the backend's `decide +native` default proof with a kernel-checked proof; its before audit exposes `_native.decide.ax_1`, while its after audit lists only the standard three axioms. Neither the portability nor these backend patches change Rust source semantics.

After installing the pinned tools with `bootstrap.sh` and `bootstrap-tool.sh`, run `bash toolchain/check-generator.sh` from this directory. It extracts fresh Charon IR for both minimized Rust reproducers, checks the patched generator's unedited output in Lean 4.34, and exercises the fail-loudly guard on referenced methodless metadata.

## Unresolved formal boundaries

The earlier public anchored `pcs::whir::verify::verify_with_basis` extraction in `WhirAeneas/Generated/Verifier` now checks under Lean 4.34, including its actual opening-record check and terminal anchor weight. Its transitive axiom audit lists only `propext`, `Classical.choice`, and `Quot.sound`. This is a checked generated function, not a theorem equating full Rust verifier behavior with the handwritten model, and it is not an extraction of the subsequent PCS overhaul. The standard-library operations have nonopaque definitions in `WhirAeneas/Std/Bulk.lean` and `WhirAeneas/Std/Guards.lean`: rotation, truncation, owned-vector extension, option equality, and slice first-element access. The recorded parent-trait generator patch resolves the duplicated `Copy` parent fields without editing generated code or the source trait. Its minimal Rust reproducer is `toolchain/tests/copy_parents.rs`. Generated template declarations are not accepted as correctness axioms.

The connected concrete native verifier is not yet fully translated. The recorded, guarded generator repair now translates the minimized monomorphized word-byte roundtrip and executes its generated definition under Lean 4.34. It skips only unused, methodless impl metadata when Charon omitted the corresponding trait declaration, and rejects a parsed fixture that references that metadata anywhere in the translated crate. The generic verifier's remaining loop-context and type-variable translation failures are not repaired by this metadata fix. Parallel and thread-local dependencies were removed from the PCS arithmetic dictionary by splitting public-column evaluation into a separate capability. No opaque substitute for a remaining verifier code path is provided, and the PCS overhaul requires a fresh coherent source extraction.

The checked standard-library lemmas are `WhirAeneas.StdBulk.collect_owned`, `extend_owned`, `rotate_zero`, `rotate_at_length`, `rotate_out_of_bounds`, `truncate_content`, and `truncate_beyond_length`. Their transitive axiom audits contain only `propext`, `Classical.choice`, and `Quot.sound`. Extracted Lean execution and the pinned Rust standard library agree on empty, zero, interior, full-length, and out-of-range rotations; truncation inside and beyond the vector length; and canonical owned-vector extension. The Rust smoke also observes panic before rotation mutation and unchanged capacity after truncation. These are logical-content lemmas and finite executions, not a verified allocator or pointer-level standard-library implementation. The extension theorem requires representable combined length and corresponds only to the canonical owned-vector dictionary used by the generated callsite; generic iterator `size_hint` side effects and unwind partial-state behavior are not covered. The arithmetic element clause carries Rust `Copy`, so truncation does not invoke element destructors in the verifier's actual instantiation. Allocation success, byte-size representability, erased capacity, allocator state, and OOM behavior remain explicit runtime boundaries.

The historical generated statement checker compiled and executed under the original supported backend. It accepted the ordinary, unaligned and high-strided-slot cases accepted by that source revision's range guards and reproduced point, ring and missing-ring errors in their original order. That result is not a statement about the current stronger guard. Its axiom audit contains only `propext`, `Classical.choice` and `Quot.sound`. The universal shift lemmas `Aeneas.Std.WrappingShiftRhs.amount_unsigned_lhs_mask`, `amount_signed_lhs_mask`, `signed_amount_unsigned_lhs` and `signed_amount_signed_lhs` have the same audited axiom set under Lean 4.34; executed high unsigned and negative signed shift cases agree with the pinned Rust release semantics. Actual native and Rows opening verification, recursive honest proving/verification and non-Boolean Merkle-selector rejection passed after the source cutovers, with byte-identical serialized proofs. Compiled operations imported from the actual handwritten `Whir.FieldTower` execute under Lean 4.34 through the canonical ring superclass dictionaries without executable finite-field enumeration. No extracted full-verifier honest/tampered execution, full acceptance/rejection correspondence theorem, security level or universal ISA refinement is claimed.

## Current hash boundary

The current source includes upstream PR 555's x86-64 compression assembly and batched Merkle hashing. These kernels are not replaced with a slower portable implementation for extraction. The compression interface is `WhirAeneas.Hash.SatisfiesRfc7693`, defined using the actual `LeanVMCircuits.Blake2s.Rfc7693.F` imported from the circuits project at `404c8fd0928ea6abea1facd220b91ee7464bd810`. That dependency and the generated portable compression both check in the same Lean 4.34 environment as the WHIR model.

`extract.sh portable` extracts the actual `primitives::hash::compress_portable` without editing its generated Lean. Execution agrees with the shared RFC definition and the native compression on both final flags and counter boundaries. These finite observations are not the universal portable-compression theorem, which remains to be proved.

The conditional native extraction separates compression and batched hash entry points from the supported verifier body. The required batch contract is content-level RFC hashing with exact output length and input order, including the zero prefix of padded leaf images. It must not assume Merkle authentication or verifier soundness. The x86 assembly, Lanes32 memory operations, and SIMD/batch backends remain tested-only boundaries until separate proofs discharge their contracts. Neither the generated function nor a conditional correspondence theorem would verify allocator, OOM, uninitialized-buffer implementation, or ABI frame behavior. This is not an unconditional Rust-to-Lean equivalence claim.

The private, single-caller `#[inline]` helper `fiat_shamir::merkle::hash_packed_leaves` belongs to the same hash boundary as `hash_pairs` and `hash_many`. Given a valid descriptor from `LeafHasher::new`, exactly `n` packed rows and successful allocation, it must return exactly `n` digests in row order. Digest `i` is the shared RFC BLAKE2s hash of the complete leaf image: the descriptor's zero prefix followed by packed row `i`. Deduplication, row count and width checks, the `row_words <= leaf_words` guard, `LeafHasher::new`, byte packing and all authentication decisions remain outside this helper and must be translated and related separately. The helper preserves the existing uninitialized allocation, fill and ownership conversion pattern; this content contract does not verify those memory operations.

On the current source based on `aeb0a3307f8c2ddef44cb69c636a81b18a98f324`, actual release-profile native and Rows opening execution accepts honest proofs and rejects the fixture's tampered proofs. The native stacked proof and separate-session recursive header and opening are byte-identical to that pinned source before the extraction-oriented repairs. The repository's alternating paired runner reported no detected throughput regression. Debug-profile native execution crashes on both the unchanged base and the repaired source, so these release observations do not claim debug-runtime correctness.

The private, inline sequential authentication-phase helpers retain Merkle validation and hashing in the translated source. Release native and Rows prove/verify/tamper execution and all three versioned proof outputs agree with source `48a5d7cd1e2db5a7cc1cbf28b57aa944836fbd13` before that split. Alternating measurements of the actual concrete native verifier fixture and an unchanged arithmetic control detect no latency regression; the longer repository paired prover workload likewise crosses no CI comparison threshold. These are scoped observations, not a universal performance guarantee. The value relation does not verify allocator capacity, OOM, or allocation and deallocation timing.

`toolchain/patch-provenance.json` is the single inventory of all carried backend, generator and Charon patches, with rationale, reproducer and hash. It distinguishes active trusted compiler changes from the inactive Box monomorphization experiment. That experiment repairs Charon's Box generic projection and typechecks its LLBC reproducer, but subsequent unsupported Aeneas pointer coercion prevents a checked generated Lean reproducer. It is not installed or silently treated as a completed extraction.

The extraction validator rejects both Charon-reported errors and references to absent function declarations before checking the requested root. Original monomorphic output has dangling synthesized array builtin references even though Charon reports no errors. The recorded, mode-scoped `charon-array-builtins-mono.patch` preserves exactly the three registered array helpers and their canonical trait metadata; synthesis fails loudly if an explicitly excluded declaration would be referenced. Its `repeat_seed` reproducer fails the original root validator, then compiles and executes unedited generated Lean after repair. The universal returned-content theorem and generated function audit contain only `propext`, `Classical.choice` and `Quot.sound`. With the sequential authentication phases, both actual generic and concrete PCS roots retain complete LLBC and pass nested-return preprocessing. Generic generation still rejects borrow and context joins; monomorphic generation rejects erased mutable-reference regions in type metadata. Neither route is claimed to have completed full verifier execution or acceptance/rejection correspondence.

After building the recorded Charon source patch, run `flock /tmp/leanvm-heavy.lock systemd-run --user --scope -q -p MemoryMax=20G -p MemorySwapMax=0 env LEAN_NUM_THREADS=2 CARGO_BUILD_JOBS=2 python3 toolchain/check-charon-array.py` in this directory. ## Current claim guard

The current source guard replaces `checked_shl` with a direct shift only after the existing exponent-below-word-width check. Checked support-dimension and block-end addition remain unchanged. Release execution at both source revisions agrees on point and strided claims, alignment and slot rejection, occupied-block rejection, addition overflow, and exponents `usize::BITS - 1` and `usize::BITS`. The actual native `StackClaim<F192>` guard has byte-identical compiled probe instructions. Native and recursive Rows prove/verify/tamper fixtures pass, and their three versioned proof outputs are byte-identical before and after this guard repair. No transcript or proof-format parameter changes.

`extract.sh statement` selects the actual generic `pcs::stack::Statement::check` with `primitives` included, so `F64::DEGREE` is generated rather than declared. The validator checks the exact inherent receiver type, retained root body, extraction errors and missing function references. The only hand-provided definition is the nonopaque `Vec::is_empty` in `WhirAeneas/Std/Guards.lean`. `WhirAeneas.ClaimShape.checkOccupied_true_iff`, `checkOccupied_eq` and `checkOccupied_full_cube` relate a dimension-first executable predicate to the real proof model at `fa13f619f560c1aa99200edbdd48480b4849b3f1`. `WhirAeneas.Claim.guard_eq_occupied`, `guard_accept_iff`, `guard_reject_iff`, `guard_accept_implies_model_accept` and `guard_full_cube_eq` relate the generated guard to that model for arbitrary claim metadata, with premises: 64-bit `usize`, `n < 64` and `committed ≤ 2^n`. The coordinate map into the model is arbitrary: this is a metadata correspondence, not a field refinement.

The occupied-prefix restriction concerns the enclosing dyadic block, not just selected strided positions. For `n = 14`, `committed = 15360`, offset and slot zero, stride exponent 14 and an empty point, the model accepts but Rust rejects. The only selected position is occupied position zero; the enclosing block reaches the unoccupied tail. Both actual executions confirm this difference. Exact equality with the model is a full-cube corollary, while the soundness-relevant implication is Rust acceptance to model shape under `committed ≤ 2^n` and the word-width layout premises. Successful source-prover openings check the same occupied-block restriction before emitting a proof. This guard slice runs before opening-record binding and does not yet cover the complete anchored verifier.

## Current statement check

Two behavior-preserving source changes make `Statement::check` extractable: it takes the `Copy` statement by value, and the per-claim span test moved into the private `const fn spans_region`. Error order, results and allocation are unchanged; native and recursive proof outputs are byte-identical to `1abc198a`, and the pcs library tests pass. `WhirAeneas.Statement.check_eq` proves the generated check returns exactly `StatementShape.check`: no ring claim first, then the first invalid region, then the first ill-formed point claim, with the same index. `check_accept_iff` is exact acceptance; `check_accept_model` derives the model's native shape premises (`SuccinctRingWeight.FamilyShape` of the flattened family in region then claim order, and `SuccinctPointWeight.Shape` of every point) from source acceptance under `log_n < 64` and `committed ≤ 2^log_n`; `check_accept_of_model` is the full-cube converse when each region carries a claim whose point spans it with 64 slices. Rust is stricter than the model exactly by the occupied-prefix block bound, the explicit region width and span checks, the rejection of claimless regions' misalignment, and the nonempty family requirement.

## Remaining generic extraction failures

`toolchain/check-loop-borrows.py` checks the pinned Aeneas outcome for each shape in `toolchain/tests/loop_borrows.rs` and fails if any outcome changes. The remaining generic verifier failures reduce to these root causes: loops while a shared borrow of a value that itself holds a shared borrow is live (`RingShare::target`, `RingShare::weight_at`, `StatementWeight::call`, `WhirReplay::terminal`, `WhirReplay::run`); a borrow returned by a call held across loop iterations or across a branch inside a loop (`RingMap::target`, `RingMap::close`); shared borrows stored in loop-carried state (`PrefixGroup::of`); a return inside nested loops (`PrunedMerklePaths::open`); and generic trait-clause type variables lost in loop and closure extraction (`LevelCtx::basis_at`, the target loop of `StackCommitment::verify`). The test-fixture root adds one harness-only assertion failure. The accepted reproducer shapes are the source workarounds: direct slice parameters or copied values, indexing instead of returned borrows, and branches moved into callees.
